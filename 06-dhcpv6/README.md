# Lab 06: Dynamic Host Configuration Protocol for IPv6 (DHCPv6)

## Overview
The primary objective of this lab is to explore and implement the three primary methods by which IPv6 end devices dynamically obtain a **Global Unicast Address (GUA)** and network parameters. Unlike IPv4, which relies entirely on stateful DHCP servers or manual configuration, IPv6 hosts automatically generate a **Link-Local Address (LLA)** (`fe80::/10`) upon interface initialization and leverage **ICMPv6 Router Advertisements (RAs)** to determine their GUA configuration method.

This lab covers three dynamic IPv6 allocation mechanisms:
1. **SLAAC Only:** Host self-generates GUA prefix and interface ID via ICMPv6 RAs (No DHCPv6 server).
2. **Stateless DHCPv6:** Host self-generates GUA via SLAAC, but queries a DHCPv6 server for additional parameters (DNS, domain name).
3. **Stateful DHCPv6:** Host obtains both its GUA address allocation and network settings directly from a central DHCPv6 server (functioning similarly to DHCPv4).

## Technical Fundamentals: IPv6 Addressing & Control Flags

### IPv6 Address Types
- **Link-Local Address (LLA) [`fe80::/10`]:** Automatically generated by every IPv6-enabled interface upon boot. Used strictly for single-subnet communication, neighbor discovery, and next-hop routing; LLA traffic cannot cross Layer 3 router boundaries.
- **Global Unicast Address (GUA) [`2000::/3`]:** Globally unique, internet-routable IPv6 address (equivalent to a public IPv4 address).
- **Unique Local Address (ULA) [`fc00::/7`]:** Routable within an internal enterprise network/organization, but dropped at the public internet edge (equivalent to private IPv4 space like RFC 1918).

### ICMPv6 Router Advertisement (RA) Control Flags
Routers periodically broadcast ICMPv6 RA messages to notify hosts how to configure their GUA. Three control flags in the RA header govern host behavior:

| Flag Name | Command / Flag Bit | Behavior / Host Action |
| :--- | :--- | :--- |
| **Autoconfiguration (A-Flag)** | `A = 1` (Default) | Instructs the host to use **SLAAC** to generate its GUA network prefix from the RA. |
| **Other Configuration (O-Flag)** | `O = 1` | Instructs the host to use SLAAC for its GUA, but contact a **Stateless DHCPv6** server for DNS/domain info. |
| **Managed Address (M-Flag)** | `M = 1` | Instructs the host to contact a **Stateful DHCPv6** server for its full GUA and network configuration. |

### Host Interface ID Generation Methods
When creating a 64-bit Host ID for SLAAC, end devices use one of two methods:
1. **EUI-64 Process:** Converts the device's 48-bit MAC address into a 64-bit ID by inserting `FF-FE` into the middle and flipping the 7th bit (Universal/Local bit).
2. **Random 64-bit Interface ID:** Modern operating systems (Windows, Linux, macOS) default to generating a randomized 64-bit number for privacy and tracking prevention (RFC 8064 / RFC 4941).

You had to make both of these changes to shift the router's behavior from being a controlling "Stateful" server to a hands-off "Stateless" one.

Here is exactly what each command did behind the scenes:

1. Why you removed address prefix (Stopping Stateful Behavior)
When the address prefix and lifetime commands are inside the pool, the router acts as a Stateful DHCPv6 server. It tries to act like a strict manager: assigning specific IPs, tracking which PC has which IP, and watching the clock to see when their lease expires.

By removing that command, you stripped the router of its IP-management duties. You turned the pool into a Stateless information booth that says, "I don't hand out IP addresses or track timers anymore. I just hand out the DNS server and domain name if anyone asks."

2. Why you added ipv6 nd other-config-flag (The "Go get DNS" instruction)
When a PC connects to your network, the router automatically sends it a beacon called a Router Advertisement (RA) with the /64 subnet so the PC can generate its own IP via SLAAC.

By default, a standard RA basically tells the PC: "Here is your subnet. Make your IP, and you are done."

When you type ipv6 nd other-config-flag, you turn on the "O" flag in that beacon. The message changes to: "Here is your subnet. Make your IP, but you are not done yet. Go ask the DHCP server for other configuration details (like DNS)."

Without removing the prefix, the router gets confused about its role. Without the "O" flag, the PCs generate their IPs but never realize they are supposed to go ask for the Google DNS server.
